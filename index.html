这一页里能看到的一切动的东西——自绘的笔迹、呼吸的星野、排序的柱子、生长的折线——都不是录屏，也不是 GIF：它们是一个 Agent 写的代码，此刻正在你的屏幕上活着跑。

约 25 分钟 4 章 · 5 个活 demo 更新于 2026.10.19

先给论点，再上证据。如果你只从这一页带走一句话，我希望是这句：对 Agent 来说，最顺手的画笔，是代码。

视频和 GIF 是一次性的——拍完、导出、定格，改一个节奏就得重新渲染一遍；代码动画是活的——改一个数字，速度变了；加一个滑杆，观众也能上手调；下一次迭代，Agent 自己就能验收：跑起来、截一帧、看一眼、再改。这篇文章里的五个 demo 都是现写的代码，你现在就能玩。

本页全部动画（包括你现在正看着的入场效果）都由一个做文章的 Agent 现场编写；五个 demo 可在浏览器里直接操作；文末列出所引用的工具与技能。

01

WHY CODE

为什么是代码：四个别的媒介给不了的

动画的载体一直在变：手绘胶片 → 数字帧 → 代码。变化的不是表现力，是"谁能改、改得多快"。

造物手记 · 01

代码动画不是新玩具：从 Flash 到 AE 表达式到 shader 玩具，工程师一直用代码控制运动。真正的变化发生在最近两年——写代码的"人"变成了 Agent，而动画恰好是它能"全链路自检"的少数媒介之一。先说结论，再列账单：

同一段 10 秒的动效，两种媒介的账
维度视频 / GIF代码动画
体积几 MB 到几十 MB几 KB 到几十 KB
清晰度受渲染分辨率限制无限，随屏幕缩放
参数化改一帧？重新导出改一行，立刻生效
交互只能播放观众也能上手调
版本管理二进制 diff 无意义每次修改都可回看、可回滚
生成成本拍摄、剪辑、渲染Agent 秒级迭代

行业里已经有人把这件事做成产品。两个信号值得注意：

SIGNAL 01Remotion：代码就是一切

64K stars 的 React 视频框架，口号是「Code is always the source of truth」；官网首页第一屏就在教你「用你的 coding agent 把想法变成视频」，还配了 Agent Skills 与插件。

SIGNAL 02Motion Canvas：描述"进行到哪一步"

用 TypeScript 生成器函数写动画：控制的是时长、速度与加速度，而不是硬编码关键帧；Vite 实时预览，改一行立刻看到——本质上是给"可迭代"设计的动画语言。

我这台机器上还装着两个更垂直的 Agent Skill：machine-skill（一句话生成单文件 HTML 物理仿真机器——我照它的流程造过一台 CG125 顶杆机的剖切台架，气门浮起的转速是解 ODE 算出来的）；3dviz-pro-max（★792 的 3D 场景技能，十步工作流里明明白白写着一步「跑起来、截帧、自审」）。它们不约而同地把"生成完必须自己看帧"写进流程——这不是巧合。

对 Agent 来说，"能写、能跑、能看、能改"四件事闭合的媒介才值得批量生产。代码动画恰好全占：能写是代码，能跑是浏览器，能看是截帧，能改是参数化。下面五个招式，每一招都给你一句可以直接抄给 Agent 的指令。

02

FIVE MOVES

五个招式：从一条笔迹到一片星野

下面每个 demo 都是独立的小世界——能跑、能调、能重播。每个后面附一句"指令模板"：就是把它交给 Agent 时，你说的话的大致形状。

每个都能玩 · 05

招式一 · 手写笔触

最古老的代码动画是"让线自己长出来"。原理一句话：把路径长度归一化成 1，用 stroke-dasharray 把整条线藏进第一段虚线，再让 dashoffset 从 1 走到 0——线的末端就成了笔尖。这是 SVG 绘制动画的祖师爷，也是 Agent 最容易做对的第一个动画。

DEMO 01 · 手写笔触

指令模板 · 手写笔触
用纯 SVG 做一段"手写笔触"动画：

1. 一条带手写质感的波浪线（三次贝塞尔），配 pathLength="1"，
   以 stroke-dashoffset 从 1 → 0 画出来；
2. 时长用 CSS 变量控制（0.4–3s 可调，页面给个滑杆）；
3. 下面叠一条更细、更浅的第二笔，延迟 0.25s 画完；
4. "重播"按钮：先移除动画类、强制重排、再加回来；
5. prefers-reduced-motion 时直接显示成品，不播动画。

验收要点：中帧体检。时长拉到 3 秒，在 1.5 秒处截一帧——你应该看到"画到一半"的线。如果中帧是空白，说明 dasharray 没归一化；如果中帧就是整条线，说明动画根本没跑，你看到的只是终态。

招式二 · 呼吸的星野

第二个招式是所有"氛围感"的底座：粒子。星野、雪、尘埃、数据流，本质是同一套结构——一堆带独立相位的小点、一个正弦时钟、再加一点视差。它的参数面天生就宽：数量、速度、幅度。而参数面越宽，越值得把控制权交给观众。

DEMO 02 · 呼吸的星野

把密度拉满、速度归零、再慢慢推回——极端参数是给动画体检最快的方式。

指令模板 · 呼吸的星野
做一个 canvas 星空，强调"可调"：

1. 星星数量默认 180、可调 60–400；每颗有独立相位，
   亮度用正弦呼吸；少数大星画成十字光芒；
2. 指针在画布上移动产生视差，越"深"的星位移越小；
3. 速度乘数 0–2×（0 时完全静止，但渲染循环照常）；
4. 适配 devicePixelRatio（封顶 2×），resize 时重建；
5. 页面切到后台时暂停 rAF，回到前台恢复。

验收要点：极端参数法。密度拉满、速度归零，截一帧——静止帧也应该好看（说明分布与亮度是设计过的，不是随机碰运气）；然后速度拉满，确认没有撕裂、没有掉帧。

招式三 · 排序竞速

第三个招式人见人爱：算法可视化。它把不可见的计算过程翻译成可见的运动。做对的关键不在"画"，在架构——算法只负责把操作录下来，播放器负责表演。这样速度可以倍速、可以回放、可以换算法对比，而算法的正确性完全不受动画影响。

DEMO 03 · 排序竞速

等待开始——比较 0 · 交换 0

指令模板 · 排序竞速
把排序算法做成柱状图动画：

1. 40 根随机高度的柱子；算法（冒泡/插入/快排）只做一件事：
   把每一次"比较"和"交换"按顺序记录成操作序列，不碰画面；
2. 播放器按速度倍率（1–60 步/秒）消费操作序列：
   比较 = 琥珀高亮，交换 = 红色闪烁，已完成区间 = 深蓝；
3. 结束后程序化断言 isSorted(arr) 为真，并把比较/交换次数
   打在图上——正确性优先于好看；
4. 速度中途可调；"新数组"重洗后不残留任何状态。

验收要点：最好的验收是断言，不是眼睛。排序结束时由代码自己证明"真的有序"；眼睛只负责检查高亮是否落在正确的两根柱子上——观察和计算各管一摊。

招式四 · 数据生长

第四个招式最实用：让数据动起来。数字滚动、折线生长、瀑布流入——报表和复盘视频里的"高级感"，大部分就是这两件事的排列组合。唯一不能让步的是诚实：数字最终必须精确等于真实值，动画的最后一帧永远输给断言。

DEMO 04 · 数据生长

0次生成 · 本季度

数字与折线在同一时刻结束——这是规格，不是巧合。

指令模板 · 数据生长
做一个"数据生长"动画卡：

1. 大数字从 0 缓动到目标值（easeOutExpo，1.6s），
   同时下方折线用 stroke-dashoffset 从左往右生长；
2. 两者必须在同一时刻结束（同一个时长的两段动画）；
3. 结束后程序化断言"显示值 === 目标值"，并让终点圆点亮起；
4. 目标值用滑杆可调，改动后自动重播；
5. 数字要带千分位，滚动过程也不乱跳。

验收要点：终点对齐。数字停在 128,410 的那一刻，折线必须刚好到顶——如果数字先停、线还在爬（或反过来），说明两个动画没有共用时间轴。截"最后一秒内"的两帧对比即可看出。

招式五 · 重力与风

最后一个招式是"手感"：物理。粒子喷泉、碎屑、弹跳——代价是要和一条铁律打交道：运动必须按时间步长归一化（dt），不能按帧计数，否则在 120Hz 屏幕上一切都会快一倍。给 Agent 的指令里，这一条要写在第一行。

DEMO 05 · 重力与风

点击画布任意处爆开一簇粒子；两个滑杆实时生效。

指令模板 · 重力与风
做一个 canvas 粒子喷泉：

1. 点击处爆开 60 颗粒子，初速度随机向上扇形；
2. 重力与风两个滑杆实时生效：v += (g, wind) * dt；
3. 着地反弹并衰减（vy *= -0.6），寿命结束后淡出移除；
4. 运动必须按时间步长 dt 归一化（dt = 两帧时间差，
   封顶 0.033s），严禁按帧计数；
5. 粒子总数设上限（如 800），超出时移除最旧的。

验收要点：把浏览器窗口切到 120Hz 屏或拉低 CPU 模拟慢速，运动速度应该不变——这是 dt 归一化的现场考试；另外把"重力归零、风拉满"，粒子应该水平流走而不是诡异下坠。

03

VERIFY LOOP

验收循环：写、跑、截帧、改

动画写完只算一半——另一半是验收。这四个字里，藏着一整个方法论。

验收方法论
  1. 跑起来才算数

    语法过、构建过都不算数；动画要在浏览器里真的动起来。最快的方式：打开它，把每一个按钮都点一遍。

  2. 截帧，而且专截中帧

    终帧会骗人——进度条到头、动画静止的最后一眼，往往完美无瑕。真正的 bug 都藏在过程里。给动画做"半程体检"：在 30%、60% 处各截一帧。

  3. 参数拉极端

    速度归零、速度拉满、密度拉爆、数值设为 0……极端参数下不崩、不丑、不 NaN，是动画上线的底线。

  4. 改的不是像素，是参数

    节奏不对？调的是参数、时长与缓动曲线，而不是"把第 43 帧往前挪两帧"。可参数化的动画，讨论的粒度是"秒"和"倍率"，不是"帧"。

一个真实的例子（就发生在做这个页面的过程中）：给文章做滚动入场动画时，终帧截图一切正常——但在 320 毫秒处截的那一帧里，页面元素全都还在隐身。问题由此现形：某种"观察机制"在内嵌浏览器里不会随滚动重发通知。终帧没告诉我的事，中帧全说了。

上线前的验收清单

这张清单可以照着做，也可以直接发给 Agent——把它当成给动画的"验收规格"，比任何形容词都有效。

04

LIMITS

边界与反例：什么时候把画笔交出去

代码动画是一种偏好，不是宗教信仰。以下场景，请把画笔让给别的媒介。

诚实汇报
实拍质感光线、皮肤、尘埃、镜头的呼吸——这些属于摄像机。代码能模拟，但没必要。
人物表演微表情与身体语言是演员的领域；代码动画里的"人物"，通常只是会动的图形符号——用来解释，不用来共情。
电影级三维复杂流体、布料、毛发解算 → 交给 Blender / Three.js 离线渲染成视频。给你一个真实数字：一段 28 秒的机器演示片，本机无头 GPU 跑了半个小时——那种工况，离线渲染才是对的。
强叙事广告片需要分镜、表演与情绪曲线的时候，视频工作流更成熟。代码动画的长处是"解释与参数"，不是"煽情"。
只看一眼的一次性内容为一次性动画搭一套参数系统是过度工程；录个 GIF 两分钟的事，别写两百行代码。

性能与可访问性三条底线：粒子数在移动端保持保守（几百级），canvas 分辨率 DPR 封顶 2×；闪烁频率远离 3–50Hz 的敏感区间；prefers-reduced-motion 时自动动画降级为静态帧、交互照常可用。

分工不是替代：视频负责"相信"，代码动画负责"理解"。一个让你身临其境，一个让你一眼看穿。

结语：短反馈回路的媒介

Agent 时代最舒服的媒介，是短反馈回路的媒介。代码动画的每一次迭代都是"改一行、看一眼、再改一行"——这正是 Agent 最强的姿势：它不需要会画画，它需要的是一个能运行、能观察、能修改的世界。

所以这一页没有一帧是录屏。你从封面滚到这里的过程，就是一次活的证据——包括你刚刚玩过的五个 demo，和此刻仍在背景里呼吸的星空。
